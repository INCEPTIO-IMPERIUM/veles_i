# Database

ฐานข้อมูลเก็บข้อมูลจริงของระบบทั้งหมด ในที่นี้คือรายวิชา CLO นักศึกษา และคะแนน หน้านี้อธิบาย schema, migration และกฎที่ห้ามพลาด

<Simple>

<Term id="schema">Schema</Term> คือ **แบบแปลนบ้าน** บอกว่ามีห้องอะไร ขนาดเท่าไหร่ ส่วน <Term id="migration">migration</Term> คือ **ใบสั่งงานก่อสร้างทีละครั้ง** เช่น "ต่อเติมห้องครัว" เก็บไว้เรียงตามลำดับ ใครมาใหม่ก็รันใบสั่งงานทั้งหมดตามลำดับ แล้วได้บ้านหลังเดียวกันเป๊ะ

และมีคำสั่งอันตรายหนึ่งคำสั่ง (`db push`) ที่ **ทุบแล้วสร้างใหม่ตามแบบแปลน** ซึ่งจะทำให้งานที่ช่างเขียนด้วยมือหายไปเงียบๆ ทีมจึงห้ามใช้ ทุกสภาพแวดล้อม

</Simple>

<Detail>

</Detail>

## กฎของ migration

<Warning title="กฎที่ห้ามพลาด 4 ข้อ">

1. เปลี่ยนโครงสร้างตารางด้วย `npm run db:migrate:dev -- --name ชื่อ_snake_case` เท่านั้น
2. **ห้ามใช้ `prisma db push`** ทุกสภาพแวดล้อม รวมถึงในเครื่องตัวเอง
3. **ห้ามแก้หรือเปลี่ยนชื่อโฟลเดอร์** ใน `database/migrations/` ที่ถูก apply ไปแล้ว เพราะ Prisma บันทึกชื่อไว้ในฐานข้อมูลแล้ว ต้องการเปลี่ยนอะไรให้สร้าง migration ใหม่
4. migration ที่เขียนด้วยมือ (SQL ล้วน) ต้องเทียบกับ shadow database ด้วย `prisma migrate diff` ก่อน apply กับฐานที่ใช้ร่วมกัน

</Warning>

<Detail>

| คำสั่ง | ใช้เมื่อ |
| --- | --- |
| `npm run db:migrate:dev -- --name <ชื่อ>` | สร้างและ apply migration ใหม่ **ในเครื่องเท่านั้น** |
| `npm run db:migrate:deploy` | apply migration ที่มีอยู่แล้ว (production และ CI) |
| `npm run db:generate` | สร้าง Prisma client ใหม่หลังแก้ schema |
| `npm run db:validate` / `db:format` | ตรวจ / จัดรูปแบบ `schema.prisma` |
| `npm run db:seed` | ใส่ข้อมูลตัวอย่าง (รันซ้ำได้ และปฏิเสธการรันถ้า `NODE_ENV=production`) |
| `npm run db:studio` | เปิดหน้าดูข้อมูลที่พอร์ต 5555 |

ถ้าแก้ `schema.prisma` โดยไม่สร้าง migration job `db` ใน CI จะล้มด้วย `prisma migrate diff --exit-code` เพราะฐานที่ migrate แล้วไม่ตรงกับ schema

</Detail>

## กฎการ query

<Simple>

เวลาไปหยิบข้อมูล ให้ขอเฉพาะที่จำเป็น และขอครั้งเดียวทีเดียวหลายอย่าง ไม่ใช่เดินไปหยิบทีละชิ้นซ้ำๆ

</Simple>

| ทำ | ห้ามทำ |
| --- | --- |
| `select` เฉพาะ field ที่ต้องการ (ไม่ส่ง `passwordHash` ออกไป) | ดึงทุก field แล้วส่งตรงให้ client |
| ใช้ `include` ดึงข้อมูลที่เกี่ยวข้องในคำสั่งเดียว | วน loop แล้ว query ทีละรอบ (N+1) |
| ครอบด้วย `prisma.$transaction` เมื่อหลายขั้นต้องสำเร็จพร้อมกัน | เขียนหลายตารางทีละคำสั่งโดยไม่มี transaction |
| ใช้ `findUniqueOrThrow` แทนการเช็ก null เอง | `$queryRaw` ถ้า Prisma ทำได้อยู่แล้ว |
| เรียกผ่าน repository เท่านั้น | เรียก `prisma.*` ใน service หรือ controller |

<Detail>

```typescript
// ✅ select เฉพาะที่ต้องการ
const course = await prisma.course.findFirst({
  where: { id: courseId },
  select: { id: true, name: true, clos: { select: { id: true, number: true } } },
})

// ✅ transaction สำหรับงานที่ต้อง atomic
await prisma.$transaction(async (tx) => {
  const course = await tx.course.create({ data: { /* ... */ } })
  await tx.cLO.createMany({ data: clos.map((c) => ({ ...c, courseId: course.id })) })
})

// ❌ N+1: query ในลูป (ยิงฐานข้อมูลหนึ่งครั้งต่อรายวิชา)
for (const course of courses) {
  course.clos = await prisma.cLO.findMany({ where: { courseId: course.id } })
}

// ✅ include ครั้งเดียว
const courses = await prisma.course.findMany({ include: { clos: true } })
```

ถ้าจำเป็นต้องใช้ raw SQL จริงๆ ใช้ parameterized (`Prisma.sql`) เท่านั้น ห้ามต่อสตริงด้วย template literal ตรงๆ

</Detail>
