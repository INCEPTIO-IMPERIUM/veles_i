# Tech Stack

Tech stack คือชุดเครื่องมือที่โปรเจกต์ใช้สร้างระบบ หน้านี้อธิบายว่าแต่ละตัวคืออะไร ทำหน้าที่อะไร และทำไมทีมเลือก (หรือเลือกไม่อัปเดต) เวอร์ชันนั้น

<Simple>

ลองนึกถึงร้านอาหาร: **หน้าร้าน** คือสิ่งที่ลูกค้าเห็นและสั่งของ (หน้าเว็บ) **ห้องครัว** รับออเดอร์ ตรวจว่าลูกค้ามีสิทธิ์สั่งไหม แล้วปรุงตามสูตร (server) **คลัง** เก็บวัตถุดิบทั้งหมด (ฐานข้อมูล) และ **ผู้ตรวจคุณภาพ** คอยเช็กทุกจานก่อนออกจากครัว (test และ CI) เครื่องมือแต่ละตัวในหน้านี้อยู่ในส่วนใดส่วนหนึ่งนี้

</Simple>

<Detail>

monorepo ที่ใช้ npm workspaces: `app/client` (React 19 + Vite 7 + Tailwind v4), `app/server` (Fastify 5 + TypeScript, ESM แบบ NodeNext: import ต้องลงท้าย `.js`) และ `database/` (Prisma 6 + PostgreSQL บน Supabase) ทั้งสองแอปไม่มี dependency ข้ามกันนอกจาก `database/schema.prisma` และสัญญา API

</Detail>

## คำขอหนึ่งครั้งเดินทางอย่างไร

<Simple>

ผู้ใช้กดปุ่มบนหน้าเว็บ → หน้าเว็บส่งคำขอไปที่ server → server ตรวจว่าเป็นใครและมีสิทธิ์ไหม → ไปหยิบข้อมูลจากฐานข้อมูล → ส่งคำตอบกลับ → หน้าเว็บแสดงผล

</Simple>

<Detail>

React + TanStack Query เรียก REST ผ่าน `apiClient` (ใส่ JWT ใน header) → Fastify: rate limit → `authMiddleware` → `authorize()` → controller → service → repository → Prisma → PostgreSQL แล้วคำตอบเดินกลับในรูป `{ success, data | message | errors }` เดียวกันทุก endpoint รายละเอียดแต่ละชั้นอยู่ในหน้า [โครงสร้างโค้ด & กฎ](/code)

</Detail>

## สำรวจเครื่องมือทีละชั้น

เลือกชั้น แล้วกดชื่อเครื่องมือ เครื่องมือที่มีเข็มหมุดสีเหลืองมี **เหตุผลที่ควรรู้** เช่น เวอร์ชันที่ตั้งใจไม่อัปเดต

## ทำไมบางตัวไม่ใช้เวอร์ชันล่าสุด

<Simple>

ของใหม่ไม่ได้ดีกว่าเสมอไป เวอร์ชันใหญ่ใหม่มักเปลี่ยนวิธีใช้งานจนโค้ดเดิมพัง ทีมจึงเลือกอัปเดตเมื่อพร้อมวางแผน ไม่ใช่อัปเดตทันทีที่มีของใหม่ ข้อไหนค้างไว้โดยตั้งใจ จะระบุเหตุผลไว้เสมอ

</Simple>

| เครื่องมือ | ใช้ | ไม่ใช้ | เหตุผล |
| --- | --- | --- | --- |
| Vite | 7 | 8 | ค้างหนึ่งเมเจอร์โดยตั้งใจ |
| TypeScript | 5.9 | 7 | 7 ใช้ตัวคอมไพล์แบบ native |
| Prisma | 6.19 | 7 | ย้ายการตั้งค่า `url` ไปที่ `prisma.config.ts` และบังคับ driver adapter ต้องวางแผนเป็นงานแยก |
| ตัวจัดการ package | npm | pnpm | ตามบันทึกเวอร์ชันของทีม |
| `xlsx` | ติดตั้งจาก CDN ของ SheetJS | ติดตั้งจาก npm registry | เครื่องมือตรวจช่องโหว่ทั่วไปมองไม่เห็นแพ็กเกจนี้ ทีมจึงมี job ตอนกลางคืนคอยเทียบเวอร์ชัน |

<Warning title="dev.md §1 บางแถวเก่ากว่าโค้ด">
